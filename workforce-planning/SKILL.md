# 人力与继任规划 (Workforce Planning & Succession Planning)

## R — 核心要旨 (Reading)

继任管理是一个全面的流程: 为每个关键岗位识别可能的继任者、并为每个人制定发展计划, 下探到高管层以下、尽可能深入组织。目标是让组织拥有一支发展充分的后备梯队, 随时准备填补出现的空缺。

---

## I — 方法论骨架 (Interpretation)

人力规划的核心不是"缺人就招", 而是先把战略目标翻译成未来的人力需求, 再做差距分析, 最后把差距变成行动计划。

1. **盘点现状** — 现有员工有什么技能与人口构成, 谁会退休/可能离职, 历史流失率多高。
2. **从战略倒推需求** — 依据战略计划里的新业务、预算、竞争与法规, 预测未来一年所需的知识/技能/能力 (KSA)。
3. **差距分析** — 现有能力 vs. 需要的能力, 判断现有员工能否培训转型、缺口多大、何时必须到位。
4. **实施并持续评估** — 把差距落成带里程碑的行动计划, 且计划要定期修订, 假设失效就更新。

继任规划是这套思路在关键岗位上的延伸, 而且它是常设流程而非一次性事件: 识别关键岗位(不止 CEO), 每岗配 1–2 名潜在继任者并各写发展计划, 用周期性人才讨论会持续更新, 深入组织各层。它可以简单到一张表。方法主张告诉员工"你在梯队里"利大于弊——这是留任高绩效者的工具。

## A1 — 应用案例 (Past Application)

### 案例 1: Xerox 2009 CEO 继任 (Mulcahy → Burns)
- **问题**: 2009 年 Anne Mulcahy 卸任 CEO, 需有人接任——一次典型的领导层更替, 组织与候选人都需要提前准备。
- **方法论的使用**: Mulcahy 在 Burns 职业生涯早期就识别其潜力, 卸任前让她在董事会面前积累经验、历练成熟; 两人约定"无论如何, 公司利益第一"。
- **结论**: 继任讨论要尽早启动, 让组织与候选人都有充分准备时间。
- **结果**: Burns 平稳接任, 交接顺利——成为"继任是常设流程而非离职时找替补"的经典正面案例。

### 案例 2: 是否告诉员工"你在梯队里"的权衡
- **问题**: 组织纠结要不要披露员工在继任名单中的位置, 怕告知后有人因没排到最高位而失望走人。
- **方法论的使用**: 方法把正反两面都摆出来, 判断"告知"的论据更强——它本身就是留任工具, 让高绩效者知道组织看重自己。
- **结论**: 告知的风险(少数人因没排到而走)值得冒, 因为这类人本就留不住。
- **结果**: 形成"继任名单透明度"的默认建议, 并把它定位为高绩效者留任手段。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 组织战略有变化(新业务线/并购/扩张/收缩), 用户问"人手怎么配、明年缺什么人"。
2. 关键岗位或领导者可能离开(退休、跳槽、突发出缺), 用户问"有没有接班人、谁来顶"。
3. 做人才盘点/九宫格/继任梯队, 用户问"怎么把这些人排进后备名单""要不要告诉他"。
4. 招聘请求漫天飞来, 用户想先判断"这是真缺人, 还是该内部培养或改流程"。

### 语言信号 (用户的话里出现这些就应激活)

- "人力/人才规划" / "编制" / "人才盘点" / "继任" / "接班人" / "后备梯队"
- "workforce planning" / "succession planning" / "talent review" / "headcount" / "pipeline" / "replacement"
- "老板突然走了怎么办" / "有没有 backup"

### 与相邻 skill 的区分

- 与 `recruiting-and-hiring` 的区别: 招聘是拿到空缺后的**执行**(漏斗、面试、录用); 本 skill 是招聘**之前**的判断——要不要招、能否内部培养、缺口何时到位。
- 与 `development-and-coaching` 的区别: 继任者发展计划是"为特定后备岗位"定向培养; 一般员工发展是开放性的成长投资。
- 与 `performance-management` 的区别: 人才讨论会借用绩效数据, 但关注点是"组织后备"而非"个人当期绩效"。

## E — 可执行步骤 (Execution)

当 skill 被激活后, agent 应按以下步骤执行:

1. **盘点当前劳动力 (现状)**
   - 完成标准: 产出当前劳动力画像(技能/人口构成/关键岗位名单) + 未来 12 个月可预见空缺清单(退休、已知离职、历史流失率推算)。
   - 判停条件: 若组织连基本的岗位与人员清单都拿不出, 先补数据源(花名册/组织图), 不要跳过现状直接谈需求。

2. **从战略倒推需求并做差距分析**
   - 完成标准: 得到未来所需 KSA 清单 + 差距表(每条差距标注"可内部培养"或"必须外部招聘"及到位时间)。
   - 判停条件: 若战略计划缺失、业务负责人无法给出未来目标, 先与业务负责人对齐假设再继续; 不要凭空编需求。

3. **把差距与关键岗位继任落成行动计划**
   - 完成标准: 每个关键岗位列出 1–2 名潜在继任者 + 各自发展计划; 行动项带里程碑; 设定周期性人才讨论会(如季度); 并记录"是否告知入选者"的决定。
   - 判停条件: 若组织没有成型的人才讨论会机制, 从一张表开始即可, 不要被复杂流程反噬。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 空缺已确认、急需立刻补人: 这是招聘执行问题, 规划不能拖延填补动作。
- 只有一两个人、没有战略计划的个体/超小团队: 四步流程的前提(战略目标、劳动力数据)不存在。
- 用户在问某个具体法律问题(如某州 WARN 期限): 这是法律合规 skill 的领地, 不是规划。

### 常见失败模式

- **流程反噬**: 继任管理被繁琐的表格和流程主导, 讨论焦点从"人的潜力"变成"走流程"; 方法明确"可以简单到一张表"。
- **无继任计划导致出缺**: 关键岗位没有后备, 领导者离开时组织被迫仓促找人——Xerox 案例的正解对照即为"等出缺才想"的失败路径。

### 方法论局限 / 适用边界

- 预设有成型 HR 部门、人才信息系统与预算——对最需要帮助的中小企业/初创是空中楼阁(可用一张表落地, 但流程本身的假设仍偏大组织)。
- 美国语境、Fortune 500 式"最佳实践"未充分讨论组织规模与行业权变。
- 方法站在雇主/HR 视角,"员工"始终是管理对象, 未讨论继任名单对员工个人的能动性与压力。

### 容易混淆的邻近方法论

- 与 `recruiting-and-hiring` 的招聘漏斗——规划是漏斗的上游, 不要在缺人时才倒过来"规划"。
- 与 `documentation-and-policies` 的人才记录——人才讨论会的产出应落到文档, 但那是记录纪律, 不是规划本身。

## 快速理解: 5 个示例问题

用这 5 个最常被问到的场景快速上手本 skill, 每个问题都对应它真正触发的处理动作:

1. **明年要开一条新业务线, 人手怎么配? 现在完全没底。** — 现状盘点 → 战略倒推需求 → 差距分析 → 行动计划
2. **CEO 三年后退休, 现在要不要开始培养接班人?** — 识别关键岗位 → 每岗配继任者 → 发展计划
3. **老板让我做人才盘点/九宫格, 继任梯队怎么落地?** — 盘点落成继任名单 + 周期性人才讨论会
4. **各部门提交了一堆招聘请求, 怎么判断是真缺人还是该内部培养?** — 需求验证 + 内部/外部差距判断
5. **有个关键岗位的老员工下个月就退休, 完全没有后备, 现在怎么办?** — 突发缺口: 临时补救 + 建常设继任流程双轨
